# Docker 版本更新总览

本节聚焦 Docker 生态的核心版本演进，覆盖 **Docker Engine**、**Docker Compose** 以及 **Docker Desktop** 的发布节奏与兼容性要点，帮助团队在进行容器化基础设施升级时做出可靠决策。

## 发布节奏概览

| 组件 | 发布周期 | 说明 |
|------|---------|------|
| Docker Engine | 约每 2 个月一个 minor 版本 | 社区版（CE）按里程碑发布，企业版（EE）滞后约 1 个月 |
| Docker Compose | 随 Engine 或独立发布 | V2 作为 Engine 插件发布，版本号与 Engine 部分解耦 |
| Docker Desktop | 约每 1-2 个月一个版本 | 同时更新 Engine、Compose、BuildKit 及 GUI 组件 |

## 版本支持策略

- **Docker Engine**：当前版本与上 2 个 minor 版本接收安全补丁
- **Docker Compose V2**：跟随 Engine 支持周期
- **Docker Desktop**：通常仅支持最新版本，历史版本按需维护

## 升级建议

1. 生产环境的 Engine 版本应尽量保持在社区支持的窗口内
2. 升级前查阅下方 Docker 兼容性矩阵，确认 Compose 文件格式与操作系统内核版本匹配
3. 涉及 Swarm 模式的集群，需逐节点滚动升级，并验证 Raft 一致性

- [Docker Compose 发布说明](https://docs.docker.com/compose/releases/release-notes/)

## Docker Compose V1 vs V2 差异说明

| 特性 | Compose V1 (`docker-compose`) | Compose V2 (`docker compose`) |
|------|------------------------------|-------------------------------|
| 实现语言 | Python | Go（作为 Engine 插件） |
| 安装方式 | 独立二进制 / pip | Engine 内置插件 |
| 命令格式 | `docker-compose up` | `docker compose up` |
| 构建引擎 | 旧版 BuildKit 支持有限 | 原生 BuildKit，性能更优 |
| 兼容性 | 已停止维护（2023年 EOL） | 当前唯一推荐版本 |
| 并行构建 | 有限 | 显著提升 |

> **重要**：Compose V1 已于 2023 年 7 月停止维护，所有环境应迁移至 V2。

## 升级检查清单

- [ ] 确认目标 Engine 版本支持当前操作系统及内核版本
- [ ] 检查 Compose 文件格式版本是否需要调整
- [ ] 验证 Swarm 集群中各节点版本一致性（建议差异不超过 1 个 minor）
- [ ] 测试 BuildKit 兼容性（如使用自定义 Dockerfile 语法前端）
- [ ] 备份 `/etc/docker/daemon.json` 及网络、卷配置
